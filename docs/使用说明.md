# AndroidLogViewer 使用说明

## 1. 准备工作

1. 用 USB 连接 Android 设备。
2. 在手机上开启“开发者选项”和“USB 调试”。
3. 如果手机弹出 USB 调试授权，请点击允许。
4. 启动 AndroidLogViewer。

程序已内置 `adb.exe`、`aapt.exe` 和相关 DLL，一般不需要额外安装 Android SDK。

## 2. 选择设备

启动后，顶部“设备”下拉框会显示当前连接的设备。

- 点击“刷新设备”可以重新扫描设备。
- 如果没有设备，检查 USB 连接、驱动、手机授权和 USB 调试开关。
- 选择设备后，左侧卸载包名下拉框会加载第三方用户应用包名。

## 3. 读取日志

点击“开始日志”开始读取当前设备的 logcat。

- 勾选“开始前清空”时，开始读取前会先执行 `adb logcat -c` 清空设备历史日志。
- 点击“停止”可以停止读取。
- 点击“清空设备日志”只清空设备端 logcat。
- 点击“清空显示”只清空当前界面显示和内存缓存。

日志列表滚动规则：

- 当前位于底部时，新日志会自动滚到底部。
- 手动向上滚动后，会停在当前位置，不会被新日志拉回底部。
- 再次滚回底部后，会恢复自动跟随。

## 4. 筛选和定位

右侧顶部筛选区提供：

- “文本”：按日志内容全文搜索。
- “Tag”：按 Android logcat Tag 过滤，多个 Tag 可用空格、逗号、分号或竖线分隔。
- “级别”：按最低日志级别筛选，支持 `All / V / D / I / W / E / F`。
- “定位”：输入关键字后点击“下一个”，或按回车，跳转到下一条匹配日志。

日志级别颜色：

- `E / F`：红色
- `W`：橙色
- `I`：蓝色
- `D`：灰色

## 5. 崩溃信息

勾选“捕获崩溃”后，程序会自动识别常见崩溃相关日志，例如：

- `FATAL EXCEPTION`
- `Fatal signal`
- `AndroidRuntime`
- `Caused by:`
- `java.lang.`
- `Exception`
- `backtrace`

“崩溃信息”页会以红色显示捕获到的崩溃相关内容。

按钮说明：

- “保存崩溃”：把当前捕获的崩溃日志保存到文件。
- “清空崩溃”：清空当前崩溃信息页。

如果当前包名不为空，崩溃发生时还会在程序目录下自动生成：

```text
crash-logs\
```

## 6. 安装 APK

把 APK 文件拖入左侧“拖入 APK 安装”区域即可安装。

拖入后左侧会显示 APK 简要信息：

- 游戏名字
- 版本
- versionCode

点击“详情”可以查看：

- 包名
- 权限列表

安装完成后，程序会自动尝试打开应用。

## 7. 强制安装

如果安装时出现签名不一致，例如：

```text
INSTALL_FAILED_UPDATE_INCOMPATIBLE
signatures do not match
```

程序会弹出提示，提供两个按钮：

- “强制安装”
- “取消”

点击“强制安装”后，程序会：

1. 先卸载设备上相同包名的旧应用。
2. 再安装当前拖入的 APK。
3. 安装成功后尝试打开应用。

注意：强制安装会删除旧应用本地数据。需要保留数据时不要使用强制安装。

## 8. 卸载应用

在左侧“卸载包名”中选择或输入包名，然后点击“卸载”。

卸载命令相当于：

```text
adb uninstall 包名
```

## 9. 保存日志

“保存日志”会保存当前缓存的日志。

“存储”下拉框控制保存级别：

- `None`：不保存
- `W`：保存 Warning 及以上
- `E`：保存 Error/Fatal
- `All`：保存全部

## 10. 分析本地日志文件

点击“分析文件”，选择 `.log` 或 `.txt` 文件。

程序会按当前筛选条件显示日志，并自动提取崩溃信息。

## 11. 语言切换

顶部语言下拉框支持：

- 中文
- English

切换后会立即更新界面主要文本、弹窗标题和状态栏提示。

## 12. 打包给别人使用

如果对方电脑没有安装 .NET，使用自包含发布：

```cmd
dotnet publish AndroidLogViewer.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=false -o D:\github\AndroidLogViewer\publish\win-x64
```

发布后把整个目录发给别人：

```text
D:\github\AndroidLogViewer\publish\win-x64
```

不要只发送单个 `AndroidLogViewer.exe`，因为程序还需要：

```text
platform-tools\adb.exe
platform-tools\aapt.exe
platform-tools\AdbWinApi.dll
platform-tools\AdbWinUsbApi.dll
```

## 13. 常见问题

### 找不到设备

检查：

- 手机是否开启 USB 调试
- 是否允许 USB 调试授权
- USB 线是否支持数据传输
- Windows 是否安装对应设备驱动
- 点击“刷新设备”重新扫描

### 安装后没有自动打开

可能原因：

- APK 没有 Launcher Activity
- 设备禁止后台启动
- 包名解析失败

程序使用以下命令启动应用：

```text
adb shell monkey -p 包名 -c android.intent.category.LAUNCHER 1
```

### APK 信息没有显示包名

程序通过 `aapt.exe` 解析 APK 信息。确认发布目录中存在：

```text
platform-tools\aapt.exe
```

### 构建时报 exe 被占用

如果看到类似：

```text
AndroidLogViewer.exe is being used by another process
```

说明程序还在运行。关闭正在运行的 AndroidLogViewer，或在 Visual Studio 中停止调试后再构建。
